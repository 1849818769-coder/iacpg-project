# 原子性违反检查清单

仅在所有项目都成立时确认 `atomicity_violation`：

1. 至少两个中断相关上下文可以交错执行。
2. 它们访问相同的共享标量、字段、指针目标或逻辑状态。
3. 至少一次访问是写操作。
4. 易受攻击的计算依赖于在多次读取间或读取/使用序列间观察稳定值。
5. 没有有效保护覆盖完整的易受攻击窗口。

## 强阳性模式
- 同一共享变量的 `R-W-R`（读-写-读）
- 同一共享变量的 `W-W-R`（写-写-读）：主程序写入后，ISR 覆写，主程序（或其调用函数）读取
- 在条件中读取，ISR写入，在赋值/表达式中再次读取
- 复合条件（&&、||、?:）中多次引用同一共享变量
- 在一个表达式内重复使用同一共享变量
- 在验证和依赖动作间计数器/标志/状态改变，当汇点不是特定的除零或数组越界时

## 拒绝作为原子性违反当
- 只有一次读取或一次写入，没有依赖的第二次观察
- 由于具体汇点，错误更适合分类为除零或数组越界
- 窗口被有效的中断屏蔽完全保护

## 报告重点
- 识别确切的读取和写入
- 展示为什么稳定观察很重要
- 解释为什么另一个缺陷族不太适合
