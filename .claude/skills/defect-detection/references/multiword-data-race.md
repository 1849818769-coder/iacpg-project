# 多字长数据竞争检查清单

仅在所有项目都成立时确认 `multiword_data_race`：

1. 变量是**多字长类型**（位宽 > 平台位宽），或存在多字配对变量（`_high` + `_low` 等模式）
2. 变量被**主程序和 ISR 双方访问**（至少一方有写）
3. 存在**可抢占窗口**（图中存在 `INTERRUPT_PREEMPTS` 关系）
4. 访问**未受锁或临界区保护**

## 强阳性模式

| 模式 | 例子 | 说明 |
|------|------|------|
| 多字长类型 | `int64_t counter` 在 32 位平台 | 赋值/读写被拆分为多步骤 |
| 多字配对 | `sec_high` + `sec_low` 组合 | 通过命名约定表示多字数据 |
| 非原子 RMW | `x = x + 1` 在 ISR 环境 | 读-改-写操作被分割 |
| 组装/拆分 | `((high << 32) \| low)` | 非原子组合操作 |

## 确认条件

1. **变量类型**：变量类型位宽 > 平台位宽（32位平台上的64位变量）
2. **变量配对**：存在 `_high` + `_low` 或类似模式的多字变量组合
3. **并发访问**：主程序和 ISR 都访问该变量
4. **可抢占**：存在中断可抢占关系
5. **无保护**：访问不在临界区内

## 拒绝作为多字长数据竞争当

- 变量宽度 <= 平台位宽（单字长访问是原子的）
- 所有访问都在临界区保护内
- 变量只在单一上下文中访问

## 报告重点

- 明确指出变量及其类型位宽
- 指出平台默认位宽假设
- 展示哪些访问跨越了原子边界
- 与 atomicity_violation 的区别：后者关注 RMW 逻辑被分割，前者关注硬件层面的非原子访问
